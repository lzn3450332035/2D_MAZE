                  / TurnResolver / BattleManager / BattleInitializer

  关键解耦手法（已定稿）：
    · Buff / 阵营行为只依赖接口 IUnitContext，不认识 UnitBase  → 打断循环依赖

    · UnitBase 死亡只发事件 OnDied，具体清理由上层订阅处理
    · DamageCalculator 全部改为纯函数（收数字、吐结果），
      需要"这个格子能不能走"时通过 Func<Vector2Int,bool> 委托注入判断

§3  规则定稿
================================================================================

--------------------------------------------------------------------------------
§3.1  战斗胜负与流程
--------------------------------------------------------------------------------
  · 可控角色：只有主角 1 人（无同伴编队）
  · 普通关卡胜利 = 双路径：
      A. 消灭全部敌人 → 奖励更优（经验 / 掉落更多）
      B. 主角走到出口 → 视为主动撤退 / 逃跑，奖励较少
  · BOSS 关胜利 = 必须击败特定 BOSS 目标
  · 失败 = 主角死亡且复活次数耗尽
  · 回合上限：无
  · 复活机制：
      - 复活次数抵消"最后一次致命伤害"
      - 原地复活，Buff 不清空，血量与能量恢复到受伤前的值
      - 复活后获得「无敌」Buff 1 回合（持续到主角下一个回合结束），该期间免疫其他伤害
      - 每次进入战斗地图时刷新复活次数
      - 初始复活次数 0，可通过装备 / 饰品增加

--------------------------------------------------------------------------------
§3.2  资源系统（能量 / 体力）
--------------------------------------------------------------------------------
  · 卡牌消耗由卡牌自身数值决定：
      - 普通物理技能卡：只消耗体力
      - 属性法术技能卡：同时消耗体力 + 能量
  · 判定规则：体力与能量任一不足 → 整张卡无法打出（AND 逻辑）
  · 战士基准值：能量 初始10 / 上限10 / 每回合+2
                体力 初始5  / 上限10 / 每回合+3
  · 初始值与上限均随角色不同而改变，上限可被装备更改
  · 战斗开始时资源恢复到【初始值】（不是上限）
  · 资源管理独立于 UnitStat，由 UnitResource（纯 C# 类，挂在 UnitBase 上）负责
  · 【待确认】回合结束时未用完的资源是否保留到下一回合

--------------------------------------------------------------------------------
§3.3  卡牌
--------------------------------------------------------------------------------
  · 伤害公式：实际伤害 = 施法者 PhysicalAtk × 卡牌倍率
  · 卡牌类别（CardType）由 CardEffectTag 自动推导，不在 Inspector 手填：
      只有 Damage          → Attack
      只有非战斗类标签      → Status
      只有 Block           → Defense
      两类及以上共存        → Mix
  · 效果标签（可叠加位标志）：Damage / Heal / Shield / Draw / ApplyBuff / Move
                              / Purge / Block
  · 动作种类（CardActionKind）：DirectDamage / Knockback / SpawnProjectile
                                / ChainLightning
  · 状态技能包含：回血、加盾、抽牌、纯上 Buff、移动、驱散
  · 防御卡：本回合抵挡一次攻击，或抵挡一次控制效果（击退 / 眩晕）
      - 「挡伤害」与「挡控制」是两个独立层，各自有次数
      - 受到攻击时消耗挡伤害层；受到控制效果时消耗挡控制层
      - 格挡成功 → 不计算伤害、不受 Buff，相当于消耗掉对方一次命中
      - 投射物被格挡后【继续穿透】，只是该目标没受伤
      - 持续 1 回合，本回合内未触发则失效
  · 稀有度：普通 / 史诗 / 传说
  · 卡牌可升级，消耗金币；不同稀有度的消耗与提升幅度不同
      需在资产中预先配置：升级提升哪个数值、每次提升多少
  · 打出的卡进入弃牌堆
  · 混合卡 = 上述任意两种及以上共存（纯 UI 分类）

--------------------------------------------------------------------------------
§3.4  牌库与手牌
--------------------------------------------------------------------------------
  · 手牌上限 10 张（可被装备更改）
  · 出战牌堆上限 25 张（可被装备更改），允许重复卡
  · 背包备用 5 张（同一轮游戏内可带入）
  · 每回合抽 3 张；补牌只补到手牌上限为止
  · 牌堆抽空时，把弃牌堆洗回牌堆
  · 「保留」机制：部分装备提供保留点数，每 1 点保留 = 每回合固定 1 张牌不进入弃牌堆
  · 构筑规则：出战 25 张中必须至少包含 2 张移动卡（或含移动效果的混合卡）
      每回合抽牌不保证手牌里有移动牌

--------------------------------------------------------------------------------
§3.5  Buff 系统
--------------------------------------------------------------------------------
  架构：配置与逻辑分离
    · BuffDataSO —— 只读配置（策划填表），运行时绝不修改
    · BuffBase   —— 运行实例，持有 CurrentDuration / CurrentStack
    · BuffManager —— 每个单位一个（纯 C# 类），只做调度，不写具体效果
    · BuffEffect 子类 —— 每种 Buff 一个文件，负责自己的效果

  BuffType：Stun / Burn / Poison / Freeze / ControlResist / Invincible
  BuffRemoveRule：TurnDuration / Permanent

  各 Buff 行为：
    Stun          固定 1 回合不能行动；可叠加延长；结束时目标 +50 控制抗性点
    Burn（灼烧）  多实例，每实例独立倒计时；每实例造成单层固定点数伤害
                  总伤害 = 层数 × 单层伤害（自然结果，不是重复计算）
    Poison（中毒）永久多层，可致死；按最大生命百分比扣血
    Freeze（冰冻）不能行动；免疫眩晕与击退；直接取消已有眩晕；
                  回合倒计时自动解除
    ControlResist 控制抗性加成
    Invincible    复活后施加，持续到主角下一个回合结束，免疫一切伤害

  跨 Buff 联动（统一放在 BuffManager.AddBuff 内，不放子类）：
    · 施加冰冻 → 清除目标身上的灼烧
    · 施加灼烧且目标已冰冻 → 触发破冰（伤害翻倍）并取消冰冻

  回合结束处理顺序（由 TurnResolver 统一驱动）：
    1. 所有单位的 Buff 结算（先扣血，再移除到期）
    2. 处理死亡（网格注销 + Buff 清空）
    3. 重算阵营效果（因为存活人数可能变化）
    4. 刷新阵营关系 / 加成缓存
    5. 检查胜负

--------------------------------------------------------------------------------
§3.6  阵营系统
--------------------------------------------------------------------------------
  三方关系（对称，一条表项管双向）：
    Ally        友军   —— 可使用友方技能，不可被选为敌方目标
    Cooperative 合作   —— 不可使用友方技能，也不可被选为敌方目标；
                          但会自行出牌攻击敌军
    Enemy       敌军   —— 可被选为敌方目标

  关系矩阵（行 = A 视角，列 = B）：
               玩家      怪物      中立
      玩家     Ally     Enemy   Cooperative
      怪物     Enemy    Ally    Enemy
      中立     Cooperative Enemy  Ally

  设计要点：
    · 彻底替代原来的 bool isPlayerTeam / TeamId 枚举
    · 单位挂载 FactionDataSO 引用，不再用团队布尔值
    · 关系表对称（一条表达双方），但【加成可非对称】：
        例：A 打 B 伤害 +20%，B 打 A 暴击率 +10% → 两条表项
    · 因此分成两张表：FactionRelationTableSO（关系）+ FactionBonusTableSO（加成）
    · 阵营效果在【回合结束】结算一次 + 战斗开始算一次初始值
    · 阵营行为既包含数值加成，也包含行为加成（对应 FactionBehaviourBase 的虚方法）
    · 未注册的 BuffType 返回 null 并报错，不静默兜底
    · 胜负判定：
        合作单位或友军死亡 → 不影响玩家收益
        敌军全灭但合作单位仍存活 → 算玩家赢
        玩家全灭但合作单位仍存活 → 算玩家输
    · 阵营SO绝不持有 Unit 引用（运行时状态不写入 SO）

--------------------------------------------------------------------------------
§3.7  移动系统
--------------------------------------------------------------------------------
  核心：主角不能自由移动，一切位移靠卡牌
    · 本回合没抽到移动卡 → 该回合无法移动
    · 出战牌堆必须至少含 2 张移动卡（构筑约束）

  朝向：
    · 持久状态，WASD 随时可改，不消耗任何资源
    · 影响：投射物发射方向、范围技能的实际范围
    · 固定方向 / 相对位置的卡 → 用 WASD 改朝向
    · 传送 / 手动选目标的卡   → 用鼠标点击选择
    · 只有上下左右四方向；斜向效果通过"多段路径"实现

  移动卡：
    · 内容不是单纯距离，而是【移动路径】，例：向前 2 格 → 向右 1 格
    · 不同卡牌的体力消耗与路径不同

  路径碰撞规则：
    · 遇障碍物 → 停在障碍前一格
    · 若第 1 格就是障碍物 → 整张卡无法打出
    · 遇友军 → 可以穿过
    · 遇敌军 → 停在敌军前一格
    · 移动经过陷阱 → 触发
    · 移动经过实体功能障碍物 → 触发；撞上则停在它前一格

  传送：
    · 可以穿过障碍物
    · 目标格（大单位为其 2×2 / 3×3 范围）内不得有：
        障碍物、实体功能障碍物、掩体 —— 任一存在即无法使用
    · 陷阱与虚体功能障碍物不阻挡传送
    · 目标格有单位 → 无法使用
    · 传送距离范围按卡牌配置

  多格单位（精英 2×2 / BOSS 3×3）：
    · 锚点 = 占用矩形的【左下角】；网格原点也在左下角（Y 轴向上）
    · 移动方案采用【方案 C】：逐格推进，某一步受阻就停在能走的最远处
      （与普通单位"停在障碍前一格"的规则保持一致）
    · 停下也算消耗了体力
    · 已知代价：永远进不了比自身窄的通道；移动 N 格要循环 N 次判定
    · 移动时把占用范围沿方向扩展 1 格，检查新增的那一条，再缩减旧条带
    · 整个单位的投影范围内有障碍物 → 无法移动
    · 可以直接改变方向，不是旋转；2×2 与 3×3 差异只有占位大小

  击退：
    · 会触发陷阱
    · 撞实体功能障碍物也触发撞墙眩晕判定
    · 单位被击退到障碍前一格，无法被击退到障碍上
    · 判定方式：即将移动到下一格时先检查，若下一格是障碍则停止并触发撞墙眩晕
    · 位移卡只能对自己使用

§3.9  障碍物
--------------------------------------------------------------------------------
  六大类：
    Wall          墙     —— 绝对不可破坏，阻挡移动与投射物
    Breakable     可破坏 —— 有血量，按 BreakableTier 限定破坏条件
    Cover         掩体   —— 有朝向；正面挡投射物，背面不挡；有血量，可破碎
    Trap          陷阱   —— 不阻挡移动，踩上触发，触发后变空地
    FieldSolid    实体功能障碍物 —— 阻挡移动，在周围范围产生效果
    FieldVirtual  虚体功能障碍物 —— 不阻挡移动，踩上触发；触发后冷却或消失

  可破坏层级（BreakableTier，7 级，先按伤害属性筛选，再看伤害形式）：
    L1 PhysicalOrMagic  物理或法术都能破
    L2 MagicOnly        仅法术
    L3 PhysicalOnly     仅物理
    L4 BurnOnly         仅灼烧
    L5 IceOnly          仅寒冰
    L6 EliteOrBossOnly  仅精英或 BOSS 单位
    L7 BossOnly         仅 BOSS 单位
    注：范围伤害 / 单体伤害 / 投射物伤害【都计入】，形式不影响层级判定

  掩体细节：
    · 从背面打 → 无法挡住伤害与投射物
    · 从正面打 → 掩体【代替承受伤害】（会掉血直至破碎）
    · 近战攻击与法术范围伤害都能对掩体造成伤害，但只有投射物会被阻挡

  视野：
    · 障碍物不阻挡对敌怪的判定（只是美术上有遮挡图像）
    · 但部分【虚体功能障碍物】可实现玩法上的遮蔽：站在其上的敌怪不可见
      → 不可被选中、不可被指定为目标，但【范围技能仍可打到】
      → 给一个半透明轮廓作为提示

  障碍物出现概率（按尺寸的密度，先按此定，后续再调）：
    9×9   81 格  12%  ≈10 个
    12×12 144 格 15%  ≈22 个
    16×16 256 格 18%  ≈46 个
    20×20 400 格 20%  ≈80 个

    各类占比：墙 35% / 可破坏 25% / 掩体 15% / 陷阱 15%
              / 实体功能障碍物 7% / 虚体功能障碍物 3%

    可破坏 7 级占比按层数递进：
                1-3 层  4-6 层  7-9 层  10 层
      L1          50%     30%     15%     10%
      L2          20%     25%     25%     20%
      L3          20%     25%     25%     20%
      L4           5%     10%     15%     15%
      L5           5%      8%     13%     15%
      L6           0%      2%      5%     10%
      L7           0%      0%      2%     10%

  硬性约束（必须写进生成器，不能只靠概率）：
    · 出生点 7×7 内禁止任何障碍物
    · 出口格禁止障碍物
    · 陷阱不得放在出生点 / 出口
    · 生成后必须 BFS 校验出生点 → 出口可达
    · 实体功能障碍物不得形成完全封闭的圈

§3.10  大世界
--------------------------------------------------------------------------------
  · 共 10 层；第 10 层固定为 BOSS 对战关；通关即游戏通关
  · 每层生成 2~3 个节点，玩家选 1 个即进入下一层（不能回上一层）
  · 节点类型：宝箱 / 战斗 / 休息 / 商店（商店也占节点名额）
  · 节点先做线性排列，后续再 UI 美化
  · 玩家能看到节点简易信息：类型 + 战斗时的地图尺寸
  · 预留随机事件拓展位

  宝箱（5 种独立类型 + 一套随机掉落表；大世界图标不区分类型）：
    普通宝箱   随机 1~2 项：50 金币 + 1 卡牌 / 50 金币 + 1 装备
                            / 100 金币 / 1 张低品质低阶卡牌
    卡牌宝箱   3~5 张卡牌
    装备宝箱   2~3 件装备

    传说宝箱   三类都出、品质更高，金币与阶数更高

    · 一轮游戏内不能换角色，只有在家里才能切换角色

    · 游戏失败时，本轮获得的卡牌与金币全部丢失（家中仓库不动）
    · 进入休息回合时可以选择提前撤退，带着已有卡牌与金币回家保存
    · 只有在【休息】和【家】中可以保存游戏
    · 在家中可花费金币升级卡牌
    · 每次进入新一轮游戏时，至多选择 25 张出战 + 5 张备用（共 30 张）
    · 界面区分：家中用「仓库」（永久收藏，分装备页与卡牌页）
                进入游戏后用「背包」（本轮携带，装备页 + 5 张备用卡）

§4.1  即时伤害 · 分段减伤（物理与元素共用同一套）
--------------------------------------------------------------------------------
  分段规则（抗性每点提供的减伤百分比逐段递减）：
     0 ~  20 : 每点 1.00%      ResistReduce_0_20    = 0.01f
    20 ~  50 : 每点 0.80%      ResistReduce_20_50   = 0.008f
    50 ~ 100 : 每点 0.50%      ResistReduce_50_100  = 0.005f
   100 ~ 150 : 每点 0.20%      ResistReduce_100_150 = 0.002f
   150 ~ 230 : 每点 0.15%      ResistReduce_150_230 = 0.0015f

  抗性上限        ResistMaxThreshold   = 230（超出部分完全不计）
  最低承伤乘子    MinDamageMultiplier  = 0.09f

  公式：最终伤害 = max(1, round(baseDamage × 承伤乘子 × 暴击倍率))

  峰值验算（抗性 = 230）：
      20 × 1.00% = 20%
      30 × 0.80% = 24%
      50 × 0.50% = 25%
      50 × 0.20% = 10%
      80 × 0.15% = 12%
      ─────────────────
      合计减伤 = 91%
      承伤乘子 = 1 − 0.91 = 0.09   ← 与 MinDamageMultiplier 必须相等

  完整减伤曲线：
      抗性    总减伤    承伤乘子   1000 伤害实际打到
        0       0%      1.000        1000
       20      20%      0.800         800
       50      44%      0.560         560
      100      69%      0.310         310
      150      79%      0.210         210
      200    86.5%      0.135         135
      230      91%      0.090          90

  ⚠️ 改任何一段系数后必须同步修改 MinDamageMultiplier，
     否则乘子会"截断"公式，把某一段的减伤曲线压平。
     （CombatConst 末尾有编辑器自检会自动报错提醒）

--------------------------------------------------------------------------------
§4.2  眩晕（减法公式）
--------------------------------------------------------------------------------
  眩晕系数        单位 = 百分点（0~100，100 = 基础必中）
  控制抗性        单位 = 点
  转换系数        ControlResistConvertPerPoint = 0.8（每点减免 0.8 个百分点）
  抗性上限        ControlResistMax = 125
                  125 × 0.8 = 100 个百分点 → 完全免疫

  公式：概率% = clamp(眩晕系数 − 控制抗性点 × 0.8, StunChanceMin, StunChanceMax)
  判定：Random.value × 100 < 概率%

  眩晕持续        StunDurationTurn = 1 回合
  眩晕结束        PostStunControlResistAdd = +50 控制抗性点（= 后续减免 40 个百分点）
  撞墙眩晕系数    WallStunCoefficient = 100

  验算表（眩晕系数固定 100）：
      目标抗性   减免(百分点)   最终概率
         0           0          100%  必中
        25          20           80%
        50          40           60%
       100          80           20%
       125         100            0%  完全免疫

--------------------------------------------------------------------------------
§4.3  延迟伤害（灼烧 / 中毒 / 破冰）
--------------------------------------------------------------------------------
  三者【共用】同一份延迟抗性点数与同一个 20 点上限，
  但各自的转换系数与数学模型不同。⚠️ 延迟伤害【没有保底】，减免 ≥ 伤害时扣 0 血。

  延迟抗性上限    DelayResistMax = 20

  灼烧（固定点数伤害）→ 减法
      每点抗性减免 1 点灼烧伤害
      BurnResistConvertPerPoint = 1f
      公式：实际 = max(0, 每层伤害 × 层数 − 抗性 × 1)
      例：抗性 20 → 减免 20 点灼烧伤害（因此每层灼烧伤害需 > 20 才有意义）

  中毒（百分比伤害）→ 减法
      每点抗性减免 1 个百分点中毒伤害
      PoisonResistConvertPercentPerPoint = 1f
      公式：实际% = max(0, 中毒% × 层数 − 抗性 × 1%)，实际伤害 = round(MaxHp × 实际%)
      例：中毒 5% × 2 层 = 10%，抗性 6 → 4%；抗性 10 → 完全免疫

  破冰（百分比爆发）→ 乘法（与上面两者不同，这是有意的）
      破冰基础 IceBreakBasePercent = 0.2（最大生命 20%）
      每点抗性减免 IceBreakResistReducePerPoint = 0.025（2.5%）
      冰冻 + 灼烧触发时 IceBreakBurnTriggerMulti = 2（翻倍）
      公式：实际% = 20% × (1 − 抗性 × 2.5%)，带灼烧时 ×2
      例：抗性 0 → 20%；抗性 10 → 15%；抗性 20 → 10%（带灼烧 20%）

  三者对"抗性 20 点"的敏感度对比（有意的不对称）：
      灼烧（若每层 30 点）  减免 67%
      中毒（若 10%）        减免 100%（完全免疫）
      破冰（20% 基础）      减免 50%

  ⚠️ 为什么中毒必须按百分点减而不是按点减：
     中毒是"最大生命的百分比伤害"。若错误地按点数减 6 点：
       目标 100 血  → 中毒 10 点，减 6 点 = 4 点  → 减免 60%
       目标 1000 血 → 中毒 100 点，减 6 点 = 94 点 → 减免 6%
       目标 10000 血 → 中毒 1000 点，减 6 点 = 994 点 → 减免 0.6%
     同样的抗性对血少的单位减免 60%、对血多的只有 0.6%，完全破坏平衡。
     按百分点减则无论血量多少减免比例恒定。

§4.4  暴击（加法 + 软上限）
--------------------------------------------------------------------------------
  【设计意图】玩家侧一律用"点数"显示，战斗侧才转成实际倍率，
             让升级加点的成长感更平滑可观。

  暴击率（加法）：
      单位       百分点（0~100）
      公式       实际暴击率% = clamp(角色点数 × 转化系数 + 卡牌点数 × 转化系数, 0, 100)
      转化系数   CritRatePointToPercent = 1（1 点 = 1 个百分点）
      上限       CritRateMax = 100（超过即必定暴击）

  暴击倍率（加法 + 软上限）：
      转化系数   CritDamagePointToMultiplier = 0.05（1 点 = 0.05 暴击倍率）
      软上限     CritDamageSoftCapPoint = 30（前 30 点全额生效）
      超出折算   CritDamageOverCapRatio = 0.5（超出部分只算一半）
      基础值     DefaultCritMultiplier = 1.5（永远参与计算的基础项，不是可替换的默认值）

      公式：
        总点数     = 角色点数 + 卡牌点数
        全额部分   = min(总点数, 30)
        超出部分   = max(0, 总点数 − 30)
        有效点数   = 全额部分 + 超出部分 × 0.5
        实际倍率   = 1.5 + 有效点数 × 0.05

      验算表：
        总点数  有效点数  倍率加成   最终倍率   边际收益
           0        0      0        1.50        —
          10       10    +0.50      2.00     每点 +0.05
          20       20    +1.00      2.50     每点 +0.05
          30       30    +1.50      3.00     ← 软上限拐点
          40       35    +1.75      3.25     每点 +0.025
          50       40    +2.00      3.50     每点 +0.025
         100       65    +3.25      4.75     每点 +0.025

      例（用户给的）：基础 1.5 + 角色 0.2 + 卡牌 0.2 = 1.9 倍
                     即：角色 4 点 + 卡牌 4 点 = 8 点 → 1.5 + 0.4 = 1.9

  ⚠️ 该设计的影响：软上限自然引导玩家分散加点，而不是无脑堆一项。
     两个参数（30 / 0.5）都是单点常量，可随时按实测数据调整。
